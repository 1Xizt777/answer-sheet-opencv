# 基线说明

这份文件记录：原始算法有哪些缺陷、每个缺陷的根因、怎么修的、修完之后测出来的数字。

原始版本是一个 553 行的单文件 OpenCV 练习项目，靠 `imshow` 弹窗肉眼判断结果。
改造分两步：

1. **加测试外壳**（算法不动）—— 解决"怎么知道改动是变好了还是弄坏了"
2. **修算法缺陷**（有度量地改）—— 解决"实际上认不准"

---

## 二、三个原始缺陷与修复

### 缺陷 1：Canny 断点 → 整张卡找不到

**现象**：`card_01_upright` 输出 `not found`，退出码 4。

**根因**：Canny 在卡片四角容易断 1~2 像素，边框环不闭合，最大轮廓面积只有 6552，
过不了 `contourArea > 20000` 的判定。

**修复**：Canny 后加闭运算补断点。

```cpp
cv::morphologyEx(edged, edged, cv::MORPH_CLOSE,
                 cv::getStructuringElement(cv::MORPH_RECT, cv::Size(3, 3)));
```

**必须用 CLOSE，不能用 DILATE**：DILATE 把边框永久外扩 1px，warp 四边形随之变大，
卡片最外圈采样到背景木纹（实测 borderMean 245 → 146），反二值化后整卡边缘连成白环，
`RETR_EXTERNAL` 只剩 1 个轮廓，气泡全被吞（73 → 1）。
CLOSE 先膨胀后腐蚀，断点补上了但边框位置复原（borderMean 保持 245）。

---

### 缺陷 2：填涂判据不成立 → 浅填涂整卡输出 `??????`

**现象**：`fillGray > 140` 的浅填涂样本准确率只有 62%，4 张卡 6 题全判 `?`。

**根因**：原判据是 `countNonZero(反二值化图) / 圆形遮罩面积`。
但 OTSU 是**整张卡求一个阈值**，被黑色标题字和气泡描边拉低（实测浅填涂卡上阈值只有 60~90）。
铅笔涂到灰度 150~178 时，反二值化后气泡内几乎全黑，占比 < 0.35 → 整行输出 `?`。
**这是判据本身不成立，不是调参问题。**

**修复**：改成"气泡内部均值 vs 周围纸面均值"的灰度对比。

```cpp
double fill = (paperMean - innerMean) / paperMean;
```

分子分母都随光照同比缩放，所以光照不均、曝光变化都不影响；铅笔深浅只改变 fill 的大小。

- 内部圆取 `0.58r`（避开印刷的圆环线条）
- 环形取 `1.25r ~ 1.70r`（气泡之间的空白纸面）

---

### 缺陷 3：第 6 题误读 → 根因不是"取最大填充"

**现象**：`slant_card` 第 6 题期望 D，实际 C。

**原 BASELINE.md 的解释是错的**（写的是"取最大填充的边界误判"）。真实根因是
**行分组没校验"每行正好 4 个"**：

`slant_card` 混进一个 `(67,761) 22x27 area=310 extent=0.52` 的墨点，
它通过了 `min_size = max(15, 767/40) = 19`（w=22 ≥ 19），
且 y=761 与第 6 行 y=747 相差 14 < 容差 35，被并进第 6 行 →
该行 5 个轮廓，按 x 排序取前 4 个时真正的 D 被挤掉。

**修复**（两道过滤）：

1. **按气泡大小一致性筛**：用所有选项宽/高的中位数做基准，`rw/rh ∈ [0.6, 1.5]` 之外的剔除。
   墨点（22x27）对中位数（89x71）的比值是 0.25/0.38，直接被踢掉。
2. **每行必须正好 4 个**：超过 4 个时，按各框高度与行内中位数的距离排序取前 4，再按 x 重排。

### 缺陷 4：斜放卡片的四边形找错（压力测试才暴露）

**现象**：200 张压力图里有 3 张定位失败 / 输出乱码，
例如 `stress_0035` 期望 `DCDA?B`，实际输出 `CD`。

**根因**：背景木纹是水平条纹，亮度梯度也在 Canny 的阈值范围内。
卡片斜放时，木纹的直边和卡片的边经常在 CLOSE 之后**连成一条线**，
最大轮廓就从卡片"漏"到背景上去了：

| 图 | raw 轮廓面积 | 凸包面积 | 凸度 | 凸包顶点 |
|---|---|---|---|---|
| stress_0035 | 155730 | 248706 | **0.626** | (833,562)(811,984)(14,918)(469,544) —— 根本不是卡片四角 |
| stress_0020 | 472212 | 525271 | 0.899 | 同上，被拉偏 |
| stress_0027 | 392494 | 466000 | 0.842 | 同上 |
| slant_card（正常） | 610989 | 612780 | 0.997 | 正确 |

warp 出来的"卡片"是斜切的一小块，气泡尺寸从 80 递减到 47，行分组只凑出 2 行。

**修复**：找卡主路线换成**亮纸掩膜**——答题卡是画面里唯一一大片高亮区域，
Otsu 一分割，纸就是白色的一个连通块，轮廓天然闭合，不受背景纹理影响。
Canny 路线降级为备选。

```cpp
cv::threshold(paper, bin, 0, 255, cv::THRESH_BINARY | cv::THRESH_OTSU);
cv::morphologyEx(bin, bin, cv::MORPH_CLOSE,
                 cv::getStructuringElement(cv::MORPH_RECT, cv::Size(9, 9)));
```

改成亮纸掩膜后，同一批图全部 n=4、凸度 ≥ 0.99（见下表）。

| 图 | Canny 路线凸度 | 亮纸掩膜凸度 |
|---|---|---|
| stress_0035 | 0.626 | **0.994** |
| stress_0020 | 0.899 | **0.996** |
| stress_0027 | 0.842 | **0.996** |
| no_card（应拒绝） | 0.264，n=6 | 0.699，n=5 → 正确拒绝 |

顺带把 `approxPolyDP` 的输入从 raw 轮廓改成凸包：卡片边缘有缺口时 raw 逼近是 5~6 个顶点，
永远过不了 `== 4`；凸包不会误伤（答题卡本身是凸四边形），凹缺口正好被填平。

## 三、阈值是怎么定的（不是拍的）

`FILL_MIN_RATIO` 和 `FILL_MIN_MARGIN` 是拿 **200 张随机扰动图**跑分布跑出来的：

```
实心填涂（1110 个）：min 0.0942  p1 0.1451  p5 0.2257  p50 0.4723  max 0.8132
空白气泡（  90 个）：全部 0.0000
未涂选项（1110 个）：全部 0.0000
```

两类之间是一整段空档。阈值定在 **0.05**：

- 比最浅的真实填涂（0.0942）低 47%，留足余量
- 又明显高于空白（0.0000），空白不会被误判成选项

> 之前定 0.12 翻过车：`stress_0089` 是"浅铅笔 + 过曝"（fillGray=177、alpha=1.15、beta=+18）
> 的极端组合，6 个选项实测 0.094~0.116，全被 0.12 挡在门外，整张卡输出 `??????`。

**教训：阈值要么从分布里读出来，要么就是猜的。**

## 五、生成器踩过的坑（记下来避免复现）

### 1. OpenCV 5.0 的多通道 `randn` 有 bug

`cv::randn` / `rng.fill(NORMAL)` 在 `CV_16SC3` 上**完全错误**：

```
3ch 16S  ch0 mean=0 std=0（没填）  ch1 mean=-22098.9  ch2 mean=-22832.9（垃圾值）
1ch 16S  mean=0.0448 std=3.02701（正常）
```

三种写法（`rng.fill(noise, NORMAL, 0, sigma)` / `rng.fill(noise, NORMAL, 0.0, sigma)` /
`cv::randn(noise, 0.0, sigma)`）全错。现象是生成的图整片深蓝。

**绕过**：先生成单通道 `CV_16SC1`，再 `split` → 每通道 `convertTo(CV_16S)` → `+= noise1`
→ `convertTo(CV_8U)` → `merge`。

另外 OpenCV 5.0 没有 `cv::RNG::setRNGSeed`，要用 `cv::theRNG().state = 7;`。

### 2. "相机没框全"是无效测试场景

卡片转出画幅会被裁成非闭合轮廓，测的是生成器不是算法。生成器必须保证整卡在画幅内：

```cpp
// 缩放上限按旋转后的包围盒算
double scaleMax = std::min(src.cols * 0.92 / wRot, src.rows * 0.92 / hRot);
scale = std::min(rng.uniform(0.45, 1.10), scaleMax);

// 位移上限也要算，不能写死 8%
double maxDx = std::max(0.0, (src.cols * 0.97 - boxW) / 2.0 / src.cols);
```

### 3. PowerShell 5.1 的 BOM 陷阱

无 BOM 的 UTF-8 `.ps1` 会把中文当 GBK 解析，报 `ParserError: 表达式或语句中包含意外的标记`。
修法：

```powershell
[System.IO.File]::WriteAllText($f, $c, (New-Object System.Text.UTF8Encoding $true))
```

## 六、已知局限

1. **只在合成图上验证过**。合成图 = 真实卡片照片 + 程序化 warp + 光照/噪声/模糊扰动，
   缺真实手机拍摄的透视畸变、滚动快门、纸张褶皱、反光斑。
2. **只支持 6 题 4 选项的固定版式**。`ANSWER` 表是硬编码的，题数、选项数、布局都不可配。
3. **支持输入（相机/GigE）没有**。目前只吃本地图片。
4. **Debug 单张 134ms**，离产线节拍（通常要求 < 50ms）还有距离，需要 Release + 优化。
5. **没有失败重试机制**。定位失败就直接返回 4，不会尝试备用预处理。
